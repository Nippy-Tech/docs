## ¿Qué hace esta vertical?

Vision es un servicio de procesamiento de imágenes que extrae datos estructurados de documentos usando Gemini Vision. **No son MCP tools** — son endpoints REST tradicionales que requieren autenticación vía `X-API-Key`.

Se usa principalmente en flujos de devoluciones (procesamiento de cédulas, licencias) y en el flujo de motoconcho (documentos de vehículos).

<Note>
  Los endpoints de Vision **no son MCP tools**. No aparecen en el listado de tools del servidor MCP. Se invocan como peticiones HTTP directas con header `X-API-Key`.
</Note>

## Endpoints de producción

### `POST /vision/process_document`

Encola un documento para procesamiento OCR en background. El documento se extrae de MongoDB, se obtiene la imagen desde S3, se procesa con Gemini Vision y el resultado se guarda de vuelta en MongoDB.

<ParamField body="document_id" type="string" required>
  El `_id` del documento en MongoDB.
</ParamField>

<ParamField body="collection" type="string" default="'motoconcho_documents'">
  Colección donde está el documento. Debe ser `"motoconcho_documents"` o `"documents"`.
</ParamField>

**Autenticación:** `X-API-Key`

**Procesamiento:**
1. Valida el `ObjectId`
2. Busca el documento en MongoDB
3. Extrae `s3`, `documentType` y `profileId` del documento
4. Genera URL firmada de S3
5. Ejecuta extracción con Gemini Vision
6. Guarda `scrapedData` en MongoDB con `status: "completed"`
7. Notifica vía Ably al perfil del usuario

**Control de concurrencia:** máximo 5 slots simultáneos (configurable con `MAX_CONCURRENT_VISION_PROCESSING`)

```bash
curl -X POST https://api.nippy.la/vision/process_document \
  -H "Content-Type: application/json" \
  -H "X-API-Key: npk_tu_api_key_aqui" \
  -d '{
    "document_id": "664f1a2b3c4d5e6f7a8b9c0d",
    "collection": "motoconcho_documents"
  }'
```

**Respuesta:**
```json
{
  "status": "accepted",
  "message": "Documento 664f1a2b3c4d5e6f7a8b9c0d encolado para procesamiento",
  "document_id": "664f1a2b3c4d5e6f7a8b9c0d",
  "collection": "motoconcho_documents",
  "slots_available": 4
}
```

### `POST /vision/analyze-invoice`

Analiza una o varias imágenes de factura desde S3 usando Gemini Vision. Extrae datos estructurados: proveedor, fecha, total e items.

<ParamField body="s3_bucket" type="string" required>
  Nombre del bucket de S3 (e.g. `"nippy-logistics"`).
</ParamField>

<ParamField body="s3_keys" type="array" required>
  Lista ordenada de claves de objeto S3 para la misma factura (máximo 3 imágenes). Ejemplo: `["returns/RTN-123/invoice-1.jpg", "returns/RTN-123/invoice-2.jpg"]`.
</ParamField>

**Autenticación:** `X-API-Key`

**Datos extraídos:**
- `proveedor` — nombre del proveedor
- `fecha` — fecha de la factura (YYYY-MM-DD)
- `total` — monto total
- `items[]` — array de productos con `descripcion`, `cantidad`, `precio`

**Deduplicación:** si se envían múltiples imágenes de la misma factura, el servicio detecta y elimina items duplicados por solapamiento entre imágenes.

```bash
curl -X POST https://api.nippy.la/vision/analyze-invoice \
  -H "Content-Type: application/json" \
  -H "X-API-Key: npk_tu_api_key_aqui" \
  -d '{
    "s3_bucket": "nippy-logistics",
    "s3_keys": [
      "returns/RTN-123/invoice-page1.jpg",
      "returns/RTN-123/invoice-page2.jpg"
    ]
  }'
```

**Respuesta:**
```json
{
  "status": "completed",
  "extracted_data": {
    "proveedor": "Distribuidora ABC S.A.",
    "fecha": "2026-05-01",
    "total": 15420.50,
    "items": [
      {"descripcion": "Mochila Nippy", "cantidad": 10, "precio": 350.00},
      {"descripcion": "Gorra Nippy", "cantidad": 50, "precio": 125.00}
    ]
  },
  "meta": {
    "input_images": 2,
    "items_before_overlap_dedupe": 5,
    "items_after_overlap_dedupe": 2,
    "overlap_duplicates_removed": 3
  },
  "error": null
}
```

### `POST /vision/analyze-administrative-invoice`

Analiza una factura administrativa desde S3 usando un prompt de Vision optimizado para finanzas. Extrae campos adicionales requeridos por flujos de registro administrativo.

<ParamField body="s3_bucket" type="string" required>
  Nombre del bucket de S3.
</ParamField>

<ParamField body="s3_keys" type="array" required>
  Lista de claves de objeto S3 (máximo 3 imágenes).
</ParamField>

**Autenticación:** `X-API-Key`

**Datos extraídos (además de los de `analyze-invoice`):**
- `titulo_factura` — título del documento
- `numero_factura` — número de factura
- `fecha_vencimiento` — fecha de vencimiento
- `moneda` — código de moneda
- `missing_fields[]` — campos que no se pudieron extraer

```bash
curl -X POST https://api.nippy.la/vision/analyze-administrative-invoice \
  -H "Content-Type: application/json" \
  -H "X-API-Key: npk_tu_api_key_aqui" \
  -d '{
    "s3_bucket": "nippy-finance",
    "s3_keys": ["invoices/ADM-456/factura.jpg"]
  }'
```

### `GET /vision/health`

Health check del servicio de Vision. Verifica conectividad con MongoDB.

**Autenticación:** `X-API-Key`

```bash
curl -H "X-API-Key: npk_tu_api_key_aqui" \
  https://api.nippy.la/vision/health
```

**Respuesta:**
```json
{
  "status": "healthy",
  "mongodb": "connected",
  "semaphore_limit": 5,
  "current_slots_available": 5
}
```

## Endpoints de testing

Estos endpoints usan un servicio mock que no consume créditos de API. Requieren autenticación vía `X-API-Key`.

| Endpoint | Método | Descripción |
|----------|--------|-------------|
| `/vision/testing/process_mock` | `POST` | Procesa un documento mock sin gastar créditos |
| `/vision/testing/stress_test` | `POST` | Ejecuta un stress test con N documentos mock (1–1000) |
| `/vision/testing/mock_stats` | `GET` | Estadísticas del servicio mock |
| `/vision/testing/supported_types` | `GET` | Lista los tipos de documento soportados en el mock |
| `/vision/testing/reset_stats` | `POST` | Reinicia las estadísticas del mock |
| `/vision/testing/health` | `GET` | Health check del servicio de testing |

### `POST /vision/testing/process_mock`

<ParamField body="document_type" type="string" required>
  Tipo de documento a simular (e.g. `"cedula"`, `"licencia"`).
</ParamField>

<ParamField body="simulate_delay" type="boolean" default="true">
  Si se debe simular la latencia de una API real.
</ParamField>

### `POST /vision/testing/stress_test`

<ParamField body="num_documents" type="integer" default="100">
  Número de documentos a procesar (1–1000).
</ParamField>

<ParamField body="document_type" type="string" default="'cedula'">
  Tipo de documento a simular.
</ParamField>

<ParamField body="delay_between_requests" type="float" default="0.0">
  Delay entre requests en segundos (0.0–5.0).
</ParamField>

## Flujo típico de procesamiento

```
1. App móvil sube documento → S3
2. App crea registro en MongoDB con s3, documentType, profileId
3. App llama POST /vision/process_document con el document_id
4. Servidor encola la tarea en background con control de semáforo (máx 5 concurrentes)
5. Gemini Vision extrae los datos de la imagen
6. Resultado se guarda en MongoDB (scrapedData + status: completed)
7. Ably notifica al perfil del usuario que el documento está listo
8. App móvil recibe la notificación y muestra los datos extraídos
```
